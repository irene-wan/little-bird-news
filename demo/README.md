# 데모: 작은 새의 소식

개인화 뉴스 서비스의 핵심 흐름을 한 번에 써 볼 수 있게 만든 작은 완성본이다.
프로필을 몇 줄 적으면, 작은 새가 오늘의 소식 가운데 세 편을 골라 **왜 골랐는지 근거와 함께** 가져온다.

정식 제품은 아니다. 정식 설계는 [`docs/architecture/technical-design.md`](../docs/architecture/technical-design.md)에 있고, 이 데모는 그 설계의 핵심만 추려 심사·시연용으로 만든 것이다.

## 써 보는 순서

1. 프로필을 적는다 (하는 일, 관심사, 잘 모르는 분야, 받고 싶지 않은 주제). "예시" 버튼으로 채워도 된다.
2. 20초쯤 기다리면 소식 세 편이 온다. 새가 날아와 전해 준다.
3. 소식마다: 질문 한 줄 → 답 → **가져온 이유와 근거** → 대표 숫자 → 핵심 3줄 → **직접 조작해 보는 설명** → 확인 문제 → 원하면 깊이 읽기와 출처.
4. 세 편을 다 읽으면 끝난다. 끝없이 이어지지 않는다.

## 세 가지 핵심 가치가 들어간 자리

| 가치 | 데모에서 |
| --- | --- |
| Personal Relevance — 나와 관련된 소식을 근거 있게 | 프로필의 **특정 문장**과 소식의 **특정 사실**이 이어질 때만 "나와 이어지는 소식"으로 고른다. 그 두 가지를 화면에 그대로 보여 준다. 이어지는 것이 없으면 억지로 잇지 않고 없다고 말한다. |
| Meaningful Understanding — 깊은 이해 | 조작형 설명(비교, 시뮬레이션, 과정), 확인 문제, 오해 방지 한 줄, 개념 풀이. 기사에 있는 사실과 AI가 보탠 설명을 구분해 표시한다. |
| Emotional Experience — 새와 함께하는 경험 | 새가 도착하고, 소식을 건네고, 누르면 반응하고, 마무리 인사를 한다. 읽는 동안에는 스스로 움직이지 않는다. |

## 어떻게 동작하나

```
[미리 준비: build-pool.mjs — 하루 한 번]
 뉴스 수집(448건) → 1차 선별 → 기사 받기 → 사실 목록 → 집필 → 검증 → 표현 시트 → 조작형 설명
                                              │                 │
                                   근거 문장이 기사 원문에      문장마다 근거 사실과 대조,
                                   글자 그대로 있는 사실만 남김   숫자는 코드로 대조,
                                                                걸리면 한 번 고쳐 쓰고 재검증
                                                        ↓
                                              data/pool.mjs (준비된 소식)

[독자가 프로필을 넣으면: api/edition.js — 약 20초]
 프로필을 항목으로 나눔 → 후보마다 "프로필 항목 ↔ 사실" 연결고리 평가(AI)
 → 선정(정해진 규칙, AI 없음) → 가져온 이유 쓰기(AI) → 이유 검증(지어낸 사정이 있으면 정해진 문장으로 교체)
```

- **사실 목록이 뼈대다.** AI가 뽑은 사실은 근거 인용이 기사 원문에 글자 그대로 있을 때만 남긴다. 본문의 "보도된 사실" 문장은 모두 이 사실 ID를 달고, 독립된 검증 단계와 코드의 숫자 대조를 통과해야 실린다.
- **선정은 규칙이 한다.** AI는 연결고리와 점수를 내고, 고르는 일은 코드가 한다. 화면의 "이 세 편을 어떻게 골랐나요"에서 모든 후보의 이유를 볼 수 있다.
- **조작형 설명은 AI가 스펙만 만든다.** 화면은 미리 만든 컴포넌트가 그린다. 스펙이 검증기(`public/validate.js`: 수치마다 근거 사실 ID, 허용된 계산식, 대조값)를 통과하지 못하면 요약 카드로 대신한다.
- **가벼운 모델만 쓴다.** `gemini-3.8-flash`와 `gemini-3.5-flash-lite`. 하루치 준비에 약 1달러, 독자 한 명의 소식을 고르는 데 수십 원.

## 개인정보

- 적은 프로필은 서버에 저장하지 않는다. 고르는 동안 AI(Google Gemini API)에 전달되고, 그 브라우저의 저장소에만 남는다.
- 저장소에는 실제 프로필, API 키, 기사 본문이 들어 있지 않다. 준비된 소식에는 사실 문장, 15~60자의 근거 인용, 출처 링크만 담는다.

## 직접 돌리기

Node 20 이상. 설치할 패키지는 없다.

```bash
# 1. 키: 저장소 루트나 demo/ 에 .env 를 만들고
#    GEMINI_API_KEY=...   (필수)
#    NEWSAPI_AI_KEY=...   (소식을 새로 준비할 때만. newsapi.ai)
# 2. 띄우기
node demo/local.mjs          # http://localhost:4175
# 3. (선택) 오늘 뉴스로 소식을 새로 준비
node demo/build-pool.mjs
```

배포는 Vercel 기준이다. 프로젝트 루트를 `demo/`로 두고 환경 변수 `GEMINI_API_KEY`를 넣으면 `public/`은 정적 파일로, `api/edition.js`는 함수로 뜬다.

## 파일

| 파일 | 하는 일 |
| --- | --- |
| `build-pool.mjs` | 오늘의 소식을 미리 준비한다 (수집부터 조작형 설명까지) |
| `lib/personalize.mjs` | 프로필에 맞춰 세 편을 고르고 가져온 이유를 만든다 |
| `lib/prompts.mjs` | 단계별 지시문 |
| `lib/llm.mjs` | Gemini 호출, 비용 계산 |
| `api/edition.js` | 요청을 받는 곳. 간단한 남용 제한 |
| `public/index.html` | 읽기 화면과 새 |
| `public/components.js`, `validate.js` | 조작형 설명 컴포넌트와 스펙 검증기 |
| `data/pool.mjs` | 준비된 소식 (자동 생성) |

## 데모라서 줄인 것

- 정식 설계에서는 본문도 독자의 지식 수준에 맞춰 쓰지만, 데모는 본문을 미리 써 두고 **고르기와 가져온 이유만** 독자별로 만든다.
- 평가(좋아요·별로예요), 지난 소식, 정정, 로그인이 없다.
- 새는 이용 조건이 확인된 기성 그림("Bird" by JcToon, Rive Marketplace, CC BY)이다. 우리 새의 그림이 아니다.
- 남용 제한은 서버 한 대가 기억하는 범위의 간단한 것이다.
