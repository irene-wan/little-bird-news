# Technical Spike S1 — 실뉴스 공급원 하나 확보

| 항목 | 내용 |
|---|---|
| 문서 상태 | **Draft v0.2**. 창업자 방향(2026-11-14)에 따라 범위를 줄였다. v0.1의 "권리 조사" 브리프를 대체한다 |
| 관련 | F-01, D-012, D-036 / PRD FR-B-01~02, FR-B-22 / `docs/architecture/technical-discovery.md` 0장 |
| 형태 | 조사와 시험 호출 |

## 1. 창업자 방향 (2026-11-14)

- MVP는 창업자 혼자 시험하는 용도여서 이용 권리는 가장 큰 위험이 아니다. 뉴스를 받아오는 것은 기본이고, 그 뒤의 기술 설계에 집중한다.
- 고품질 공급원 **하나만** 확보하면 된다. 넓게 조사하지 않는다.
- 가입과 약관 동의로 끝나는 일은 창업자가 직접 하고 키를 넘긴다.
- 공급원에 문의해야 할 만큼 복잡한 경로는 버린다. 문의 초안도 만들지 않는다.
- 권리가 확인되지 않아도 실제 보도 본문을 AI 실험에 넣는다.

이 방향으로 PRD FR-B-01, NFR-R-01, P-11, F-01이 요구하는 권리 확인은 프로토타입 뒤로 미뤄졌다. 본인 외의 사람에게 제공하기 전에는 다시 확인해야 한다 (CLAUDE.md 「보안·개인정보」의 공개 전 점검과 같은 취지).

## 2. 목적

국내 뉴스의 **본문 전체**와 출처, 발행 시각, 원문 주소를 받을 수 있는 공급원 하나를 확보해 핵심 가치 프로토타입의 입력으로 쓴다.

## 3. 지금까지 확인한 것 (2026-11-14, 각 서비스의 공식 문서 기준)

| 후보 | 본문 전체 | 가입 | 확인한 내용 | 확인하지 못한 내용 |
|---|---|---|---|---|
| **newsapi.ai (Event Registry)** — 1순위 | 문서상 제공 (요청 옵션으로 본문 길이를 전체로 지정) | 이메일 가입, 결제수단 불필요 | 무료 2,000건(토큰), 같은 사건의 기사를 묶은 "event" 단위 검색이 모든 요금제에 포함, 동시 요청 5개 | **한국어 기사와 국내 매체의 수록 범위**, 무료 키로 본문 전체가 오는지, 무료 플랜의 기간·이용 조건. 키를 받아 시험 호출 한 번으로 확인한다 |
| **네이버 뉴스 검색 API (NAVER API HUB)** — 2순위 | 없음. 제목, 요약 발췌, 원문 주소, 발행 시각만 온다 | 네이버 클라우드 플랫폼 콘솔에서 이용 신청 후 Application 등록 | 하루 25,000회, 국내 매체 범위가 넓다. 예전 developers.naver.com의 키는 새 주소에서 쓸 수 없다 | 요금과 결제수단 등록 필요 여부. 본문은 원문 주소에서 따로 가져와야 한다 |
| 빅카인즈 | 미확인 | 미확인 | 분석 기능 API가 공공기관·연구단체에 제공된다는 보도자료 | 개인 신청 가능 여부와 본문 제공. 신청·심사가 필요해 보여 "복잡한 경로"로 보고 제외한다 |
| 딥서치 뉴스 API | 미확인 | 문의 방식 | 공개된 가입·요금 안내를 찾지 못했다 | 전부. 문의가 필요해 제외한다 |

## 4. 진행 방법

1. 창업자가 newsapi.ai에 가입해 API 키를 받아 프로젝트의 `.env` 파일에 넣는다.
2. 시험 호출로 확인한다: 한국어 기사가 충분히 오는가, 본문 전체가 오는가, 매체·발행 시각·원문 주소가 오는가, 하루치 국내 뉴스를 받는 데 무료 한도의 얼마를 쓰는가.
3. 한국어 수록이 부족하면 2순위(네이버 뉴스 검색 API로 목록을 받고 원문 주소에서 본문을 가져오는 방식)로 넘어간다.

## 5. 검증 기준

| # | 기준 |
|---|---|
| 1 | 국내 뉴스 하루치를 본문 전체, 매체, 발행 시각, 원문 주소와 함께 받아 저장했다 (FR-B-02) |
| 2 | 받은 기사 수, 매체 분포, 본문이 비었거나 잘린 기사의 비율을 기록했다 |
| 3 | 하루치를 받는 데 든 호출 수와 비용을 기록했다 |
| 4 | 이 공급원으로 프로토타입을 진행할 수 있는지, 안 되면 무엇이 부족한지 명시했다 |

## 6. 결과 (2026-11-15 시험 호출)

창업자가 newsapi.ai 키를 발급했다. `spikes/news-source/fetch-sample.mjs`로 기사 1회, 사건 1회를 호출했다. 받은 원본은 Git에 올라가지 않는 `private/news-samples/`에 있다.

**결론: 이 공급원으로 프로토타입을 진행할 수 있다.** 2순위(네이버)로 넘어갈 필요가 없다.

| 확인 항목 | 결과 |
|---|---|
| 한국어 기사 수록 | 최근 30일 한국 매체의 한국어 기사 315,954건 (하루 약 1만 건) |
| 매체 | 표본 100건에서 16곳: 매일경제, 한국경제TV, 연합뉴스, 문화일보, 더팩트, 동아일보, 한국일보, YTN, 국제신문, 경향신문, 국민일보, 파이낸셜뉴스, 오마이뉴스 등 |
| 본문 전체 | 100건 모두 본문이 왔다. 길이 365~6,415자, 중간값 1,103자. 빈 본문 0건 |
| 출처·시각·원문 주소 | 100건 모두 매체명, 발행 시각, 원문 주소, 대표 이미지 주소가 있다 (FR-B-02) |
| 사건 묶음 | 공급원이 같은 사건의 기사를 묶어 준다. 최근 30일 한국어 사건 36,133건 (하루 약 1,200건). 사건마다 제목, 요약, 기사 수가 온다. 표본의 사건당 기사 수는 6~17건 |
| 속도 | 호출당 1.7~2.3초 |
| 사용량 | 기사 100건 호출 1토큰, 사건 50건 호출 5토큰. 지금까지 6토큰 사용, 1,994토큰 남음 |

**수집 방식 (엔지니어 선택)**: 하루 1만 건을 전부 받으면 하루 100토큰쯤 들어 무료 한도가 20일이면 끝난다. 그래서 사건 목록을 먼저 받아 기사 수가 많은 사건부터 추리고, 후보가 된 사건의 기사 본문만 받는다. 하루 30~50토큰 정도로 예상하며 실제 사용량은 프로토타입에서 기록한다.

## 7. 관찰한 한계

- **표본은 한 번, 100건이다.** 토요일 밤 9시 반부터 자정 넘어서까지 3시간 남짓의 기사여서 평일 낮의 매체 분포와 다를 수 있다.
- **본문에 군더더기가 붙어 온다.** "좋아요 00 싫어요 00", 저작권 문구, 제목 반복 같은 것이 본문 끝에 섞여 있어 정리 단계가 필요하다. 매체 이름 한 곳은 글자가 깨져서 왔다.
- **같은 통신사 기사가 여러 매체에 그대로 실린다.** 공급원의 중복 제거 옵션을 켰는데도 100건 중 3묶음(6건)이 같은 제목이었다. 사건 정리 단계에서 걸러야 한다.
- **최신 기사는 아직 사건에 묶여 있지 않다.** 100건 중 38건만 사건 번호가 있었다. 묶이는 데 시간이 걸리는 것으로 보인다. 얼마나 걸리는지는 확인하지 않았다.
- **국내 매체가 쓴 해외 사건이 섞여 온다** (예: 프랑스 시위, 쿼드 정상회의). "국내"의 경계(FR-B-22)를 정할 때 실제로 부딪히는 문제다.
- **공급원의 사건 묶음이 얼마나 정확한지는 평가하지 않았다.** 프로토타입에서 직접 본다 (D-013).
- **이용 권리는 확인하지 않았다.** 창업자 방향에 따라 프로토타입 뒤로 미뤘다. 참고로 표본 100건 중 19건(연합뉴스 계열)의 본문 끝에 "무단 전재-재배포, AI 학습 및 활용 금지" 문구가 들어 있다. 본인 외의 사람에게 제공하기 전에 반드시 다시 봐야 하는 지점이다.
- 무료 플랜의 기간 제한과 이용 조건은 확인하지 않았다.
