# Technical Spike S7 — 개인정보·접근 제어·프로필 모델

## 1. 목적

실제 프로필을 외부 AI에 전달하기 전에 정해야 하는 것(Q-11)을 창업자가 결정할 수 있도록 근거 자료와 선택지를 만든다. 개인화 추천 Spike(S3)에서 실제 프로필을 쓰려면 T-03의 임시 결정이 먼저 있어야 한다.

## 2. 범위

**포함**

| 주제 | 다루는 내용 | 관련 |
|---|---|---|
| 외부 AI 전달 | AI 공급사 후보의 API 데이터 조건(보관 기간, 학습 사용 여부, 보관하지 않는 옵션, 처리 지역)을 공식 문서로 확인. 단계별로 어떤 프로필 정보가 필요한지 정리. 임시 전달 규칙 초안 | T-03, NFR-S-03~04 |
| 접근 제어 | 신원 확인 프록시 / 앱 내 단일 계정(패스키) / 사설망 방식의 비교. 다중 사용자 체계 없이 본인만 접근하는 조건에서의 장단점 | T-02, NFR-S-01 |
| 저장과 보호 | 저장 위치의 선택지(내 장비 / 클라우드)와 저장·전송 중 보호 방식, 평가·추적 기록 속 개인 정보의 보호 | NFR-S-02, NFR-S-06 |
| 삭제와 재실행의 충돌 | 선택지(완전 삭제 / 내용 가림 / 기간 보존 / 삭제 시 선택)마다 재실행(FR-G-05)과 삭제 통제(P-10)에 주는 영향 | D-034, T-04, NFR-S-05 |
| 프로필 데이터 모델 | 항목 단위 모델 초안: 선택형·서술형, 직접 입력과 AI 추론의 구분, 수정 이력, 민감도, 시효, 추천 시점의 스냅숏. 최소 시작 항목의 선택지 | D-011, FR-A-02~08, FR-A-11, NFR-M-03 |
| 민감 정보 | 허용 범위를 정하는 데 필요한 선택지 정리 | Q-11, FR-A-09 |

**제외**

- 결정. T-02, T-03, D-011, D-034는 창업자가 정한다
- 실제 개인정보의 사용. 예시는 모두 가짜 값으로 쓴다
- AI 공급사 선정과 계정 생성
- 법률 자문

## 3. 방법

1. AI 공급사 후보의 공식 약관과 데이터 처리 문서를 읽고, 근거 문서의 위치와 확인 날짜를 기록한다.
2. PRD 2.7절의 단계별로 프로필의 어떤 부분이 실제로 필요한지 표로 정리한다.
3. 접근 제어와 저장 방식을 같은 항목(본인 전용 보장, 폰에서의 사용 편의, 운영 부담, 실패 시 노출 범위)으로 비교한다.
4. 가짜 프로필로 항목 모델 초안을 써 보고, PRD 요구사항 점검표로 확인한다.
5. D-034의 선택지별로 "삭제 뒤 무엇이 남고 무엇을 다시 돌릴 수 있는지"를 가짜 사례로 보여 준다.

## 4. 검증 기준

| # | 기준 |
|---|---|
| 1 | AI 공급사 데이터 조건에 대한 모든 서술에 공식 문서의 위치와 확인 날짜가 있다. 확인하지 못한 조건은 "미확인"으로 표시되었다 |
| 2 | 임시 전달 규칙 초안이 단계별로 무엇을 보내고 무엇을 보내지 않는지 명시한다. 민감 정보는 정책이 정해지기 전까지 전달하지 않는다 (Q-11) |
| 3 | 접근 제어 방식 세 가지가 같은 항목으로 비교되었다 |
| 4 | 프로필 모델 초안이 FR-A-02~08, FR-A-11, NFR-M-03 각각을 어떻게 만족하는지 점검표로 확인되었다. 가짜 데이터만 썼다 |
| 5 | D-034의 선택지마다 FR-G-05, NFR-S-05, P-10에 주는 영향이 적혀 있다. 어느 쪽도 가정으로 고르지 않았다 |
| 6 | Technical Discovery 3.1절 3번(삭제된 프로필 내용의 우회 유입)에 대한 경로 분석이 포함되었다 |

## 5. 산출물

- AI 공급사별 데이터 조건 표와 근거 목록
- 임시 전달 규칙 초안 (Proposed)
- 접근 제어·저장 방식 비교표
- 프로필 항목 모델 초안과 요구사항 점검표 (Proposed)
- D-034 선택지와 영향 분석
- D-011, D-034, T-02, T-03에 대한 Decision Log 변경안 초안 (Proposed)
