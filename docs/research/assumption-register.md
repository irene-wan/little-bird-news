# Assumption Register

**개인화 뉴스 서비스 | v1.0 · 승인된 가설 관리 계획 | 2026-11-13**

## 1. 목적과 검증 범위

최초 MVP는 창업자 본인 한 사람에게 Personal Relevance, Meaningful Understanding, Emotional Experience가 실제로 전달되는지 평가한다. 가설 관리 계획이 승인되었다는 것과 가설 자체가 검증되었다는 것은 다르다.

- P0: 최초 개인용 MVP 합격에 필요한 핵심 가설
- P1: 핵심 경험을 정교하게 개선할 가설
- P2: 외부 사용자 확대 시 검토할 가설
- 상태값: Unvalidated / Testing / Supported / Contradicted / Inconclusive / Revised

## 2. P0 — Personal Relevance

### H-01. 뉴스 탐색과 이해의 부담은 해결할 가치가 있는 실제 문제다.

기초 근거: 창업자 직접 경험과 초기 VOC. 평가: 기존 뉴스 이용의 탐색 시간과 불편, 대안의 만족도를 기록한다. 서비스가 사용자의 실제 부담을 개선하는지 확인한다.

### H-02. 정교한 개인화가 의미 있는 소식을 발견하게 한다.

평가: 날짜와 분야를 달리하며 추천 목록을 반복 평가한다. 일반 뉴스 피드, 인기순, 직접 찾은 소식과 비교한다. 관련성·새로운 발견·중요 소식 누락·부적절한 추천을 함께 기록한다. 실패 사례는 원인을 분해해 보존한다.

### H-03. 정확한 추천 이유가 이해받는 느낌을 강화한다.

평가: 추천 이유가 실제 사용자 입력 정보 및 기사 사실과 일치하는지 확인한다. 추천 이유의 자연스러움, 설득력, 과장된 추론 여부를 기록한다.

### H-08. 구체화된 프로필이 추천 품질을 높인다.

평가: 간단한 프로필과 확장된 프로필을 기준으로 추천을 비교한다. 정보량뿐 아니라 정확성, 최신성, 잘못된 추론 누적 여부를 확인한다.

## 3. P0 — Meaningful Understanding

### H-04. 맞춤형 설명이 일반 뉴스 요약보다 이해 만족을 높인다.

평가: 원문, 일반 요약, 개인화된 설명을 적절한 사례에서 비교한다. 이해도·추가 검색 필요성·흥미·기억에 남는 내용을 기록한다.

### H-12. AI 인터랙티브 설명이 개념 이해에 기여한다.

구현 범위: 최초 MVP 필수. 관계도·흐름도·조작형 계산 또는 비교 등 적합한 형식을 실제로 렌더링한다. 조작 가능 여부, 개념 이해, 혼란과 잘못된 도식·수치 발생을 평가한다.

### H-15. 개인화된 집필과 편집이 프리미엄 콘텐츠 만족을 만든다.

평가: 단순 요약과 편집된 콘텐츠를 비교하고 흥미, 정보의 밀도, 기억에 남는 핵심 지식, 읽는 시간의 가치를 기록한다.

## 4. P0 — Emotional Experience

### H-05. 끝이 있는 소식 경험이 만족과 피로 감소에 기여한다.

평가: 이용 전후 피로·만족·성취감과 종료 경험을 기록한다. 읽고 난 뒤에도 숙제 같은 부담이 남는지 확인한다.

### H-10. 새의 움직임과 반응이 정서적 만족에 기여한다.

구현 범위: Rive 기반 최소 상호작용을 먼저 시도한다. 새의 등장·전달·터치 반응·마무리를 체험하고 귀여움, 힐링감, 읽기 방해 여부를 평가한다.

### H-16. 새가 전달과 설명에 일관되게 참여할 때 관계감이 생긴다.

평가: 시작·소식 전달·설명·마무리가 하나의 캐릭터 경험인지 평가한다. 화면 장식으로 느껴지는지, 친숙함이나 재방문 의향이 생기는지 기록한다.

## 5. P1 — 후속 개인화·UX 가설

- H-06: 하루 소식 3개가 적합하다. 수량은 미확정이며 여러 구성을 비교한다.
- H-07: 캐릭터 대화형 온보딩이 직접 입력보다 자연스럽다. 최초 MVP에서는 직접 입력한다.
- H-09: 새로운 분야의 소식이 발견의 즐거움을 만든다. 억지 개인화는 허용하지 않는다.
- H-11: 뉴스를 놓친 날에도 부담 없는 설계가 복귀를 돕는다. 장기 사용 시 검증한다.
- H-13: 새가 돌아오는 시간을 기다리는 경험은 설렘을 만든다. 추후 비교한다.
- H-14: 새의 말투와 성격 선택이 만족을 높인다. 후속 검증 항목으로 보존한다.

## 6. Technical Feasibility Gates

### F-01. 뉴스 데이터 이용 권리

수집·저장·AI 처리·재가공·사용자 제공 권리를 소스별로 확인한다. 권리가 불명확한 소스는 실서비스 파이프라인에서 제외한다.

### F-02. 사건 단위 뉴스 후보 생성

중복 기사 병합, 동일 사건의 식별, 다른 사건과의 구분, 게시 시각과 출처 보존, 후보 누락 평가가 가능해야 한다.

### F-03. 개인화 추천 평가

후보별 관련성 근거, 선정·제외 이유, 모델 버전, 개인화 입력을 기록하여 결과를 비교한다. 설명이 아니라 검증 가능한 추천이 목표다.

### F-04. 사실성 있는 집필

생성된 문장을 출처와 연결하고 사실·해석을 구분한다. 오류 검출과 발행 보류·수정 절차가 있어야 한다.

### F-05. 인터랙티브 UI의 신뢰성

AI가 승인된 컴포넌트와 검증된 구조화 데이터로 내용을 구성한다. 값 범위·수치·모바일 동작을 검사하고 실패 시 대체 설명을 제공한다.

### F-06. Rive 초기 프로토타입

1~2일 목표로 작게 시작한다. 등장·전달·반응·마무리의 필요한 최소 상태를 구현하고 모바일 동작, 애셋 난이도, 확장 가능성을 기록한다.

### F-07. 개인 정보 보관 및 접근 통제

프로필의 추가·수정·삭제, AI로 전달되는 정보의 최소화, 저장 위치, 접근 권한과 민감정보 처리를 검토한다.

## 7. 개인용 MVP 검증 프로토콜

- 최소 서로 다른 5~7회의 사용 세션을 초기 제안으로 삼고 필요에 따라 확장한다.
- 매 회차: 사용 날짜, 프로필·모델 버전, 추천 목록, 선정 이유, 관련성 평가, 이해한 내용, 인터랙션 동작, 감정 평가, 실패 사례를 기록한다.
- 평가 전 기대했던 사건이나 소식을 별도로 적어 중요한 누락을 확인한다.
- 일반 피드나 직접 검색 결과를 비교 기준선으로 활용한다.
- 세 가치별 Pass / Needs Improvement / Fail을 판정한다.
- 구체적인 정량 합격 기준은 실험 시작 전에 별도 Evaluation Spec에서 확정한다.

## 8. 완료와 한계

각 P0 가설은 구현했다는 이유만으로 Supported가 되지 않는다. 실제 사용과 오류 기록, 반복적인 비교를 통해 상태를 변경한다. 세 가치가 모두 Pass이고 중대한 콘텐츠·보안 품질 문제가 해결되면 개인용 MVP를 통과한다. 이는 시장 수요에 대한 통계적 검증을 의미하지 않는다.
