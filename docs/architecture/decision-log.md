## 2. Confirmed — 제품·개발 방향

### 2.1 2026-11-13 확정 (v1.0)

#### D-000. 원본 기획서 보존

뉴스 서비스 기획서 v3를 원본 Vision Document로 보존한다. Product Brief, 원칙, 가설, 후속 PRD 및 기술 설계는 별도 버전으로 관리한다.

#### D-001. 서비스 문서 용어

프로젝트명은 '개인화 뉴스 서비스'로 표기한다. 뉴스 콘텐츠는 일관되게 '소식'이라 부른다. 원본 v3 문서는 수정하지 않는다.

#### D-002. 최초 MVP 사용자는 한 명

창업자 본인을 대상으로 개인용 제품을 만든다. 다중 사용자 계정과 외부 고객 획득 기능은 최초 MVP에서 제외한다.

#### D-003. MVP 필수 합격 가치

Personal Relevance, Meaningful Understanding, Emotional Experience 세 가지 모두 구현·검증한다. 한 가치라도 미달하면 전체 MVP를 완료로 보지 않는다.

#### D-004. 최초 프로필 입력

모바일에서 사용자가 직접 프로필을 입력·수정한다. 소수 정보로 시작해 점진적으로 확장 가능한 구조를 갖춘다. 새와의 대화형 온보딩은 장기 비전으로 유지하되 최초 MVP에서는 구현하지 않는다.

#### D-005. 추천 품질 최우선

사건 정리, 개인화 관련성, 추천 이유를 검증 가능하게 개발한다. 임시 키워드 매칭을 품질 입증 없이 최종 시스템으로 간주하지 않는다. 세부 알고리즘은 아직 결정하지 않았다.

#### D-006. 개인화 프리미엄 집필

AI는 최종 선정된 사건을 사용자에게 적합한 정보 밀도·설명 수준·관점으로 집필한다. 사실과 해석을 구분하고 출처를 보존한다.

#### D-007. 인터랙티브 콘텐츠 필수

최초 MVP에서 설명 목적에 적합한 AI 인터랙티브 지식 콘텐츠를 실제 구현한다. 텍스트 요약만 있는 서비스는 합격할 수 없다.

#### D-008. 정서적 캐릭터 경험 필수

새의 등장·전달·터치 반응·마무리 중 최소한의 실제 상호작용을 구현한다. Rive를 최우선 검토하고 1~2일 규모의 제한된 프로토타입으로 가능성을 확인한다. Rive 최종 채택과 애셋 구성은 검증에 따른다. (D-026, D-031이 보완)

#### D-009. 주변 기능 범위 제외

소셜·결제·복잡한 보상·캐릭터 수집·다중 사용자 운영·무한 피드는 최초 MVP의 범위 밖이다. 개인정보 보호·출처·테스트·오류 처리는 예외로 필수다.

#### D-010. Product Brief 검토 기준

창업자가 직접 수정한 Product Brief 1~7.6과 이후 승인한 핵심 MVP 방향을 제품 정의의 기준으로 사용한다. 현재 문서 v1.0은 그 내용을 반영한 운영 버전이다.

### 2.4 2026-11-14~15 확정 (v1.3 추가) — Technical Discovery 중 창업자 방향

## 3. Pending / Validation Required — 앞으로의 기술 결정

v1.0의 본문은 그대로 두고, v1.1에서 덧붙인 조건은 "v1.1 추가"로 표시했다.

### D-011. 프로필 데이터 모델 [Pending]

구조화 필드·서술형 정보의 혼합 구조를 우선 검토한다. 수정, 데이터 출처, 민감정보·장기 기억 분리를 설계한다.

### D-012. 뉴스 데이터 공급원 [Pending · Critical]

이용 권리, 최신성, 처리·재가공 허용 범위, 공급 안정성과 비용을 조사한 후 선정한다. 검증 전 특정 API에 종속되지 않는다.
*v1.1 추가*: MVP는 국내 뉴스로 한정한다 (D-036). 자료사진이 대체 시각 요소로 쓰이므로 사진의 이용 권리도 함께 확인한다 (D-039).

### D-013. 사건 병합·후보 생성 [Pending]

수집 범위와 주기, 중복 제거, 같은 사건 판별, 후보군 평가와 누락 관리를 정의한다.

### D-014. 개인화 추천 알고리즘 [Validation Required]

규칙, 검색·임베딩, LLM 심사, 다단계 혼합 파이프라인을 비교한다. 추천 정확도·설명 근거·비용·지연시간이 선정 기준이다.

### D-015. AI 집필 및 품질 검증 [Pending]

출처-문장 연결, 사실·해석 분리, 생성 품질 평가, 검증 실패 시 보류 절차를 결정한다.

### D-016. AI 인터랙티브 UI 기술 [Validation Required]

자유 코드 생성보다 검증된 컴포넌트와 구조화된 UI 데이터 방식부터 시험한다. 실제 모바일에서 조작·렌더링·수치 검증을 확인한 뒤 기술을 채택한다.
*v1.1 추가*: 서로 다른 최소 2가지 인터랙티브 방식이 실제로 동작해야 한다. 관계·과정·비교·시뮬레이션 가운데 적합한 유형을 검토한다. 구체적인 컴포넌트 종류와 기술 구현은 Technical Discovery에서 결정한다 (D-025). 인터랙티브가 어색한 소식에 넣을 대체 시각 콘텐츠의 제작 방식도 함께 정한다 (D-039).

### D-017. 새 캐릭터 애셋과 Rive 상태 [Pending]

새 디자인, 애셋 제작 방식, state machine 상태, 모바일 성능, 1~2일 프로토타입 범위를 결정한다.
*v1.1 추가*: 네 순간 모두에 참여하되 제한된 애니메이션 상태를 재사용해도 된다. 짧은 상황별 대사의 범위와 작성 방식을 함께 정한다. 기술 변경은 부적합 증거와 창업자 승인이 필요하다 (D-026, D-027, D-031).

### D-018. 개인용 MVP 정량 합격선 [Pending · Critical]

세 가치의 반복 측정과 Pass 기준을 Evaluation Spec에 기록한다. 만족도를 자신에게 유리하게 사후 조정하지 않도록 평가 전에 정한다.
*v1.1 추가*: Evaluation Spec에 다음을 포함한다. 주제 영역 목록과 기준 / 자연 추천 소식과 고정 기술 테스트 사례의 결과를 합격 판정에 반영하는 방법 / 고정 기술 테스트 사례의 구성 / 독립 뉴스 표본의 확보 방법과 주기 / 모델 평가와 체험 평가의 구분 기록 / 간단 평가 항목의 최소 구성 / 인터랙티브 설명이 들어간 소식의 비율 기준 (D-024, D-025, D-029, D-030, D-039).

### D-019. 하루 소식 수량 [Validation Required]

소수의 고품질 소식이라는 방향은 확정됐다. 3개 고정 또는 다른 수량은 실제 체험 후 결정한다.

### D-020. 소식 도착 시간과 알림 [Deferred]

정시 도착과 기다림의 설렘은 장기 제품 경험으로 보존한다. 초기 핵심 기술 검증의 선행 조건은 아니다.

### D-021. 장기 기억과 자동 학습 [Pending]

직접 입력과 명시적 피드백을 우선한다. 자동 추론과 장기 보관은 개인정보·품질 기준을 세운 뒤 확장한다.

### D-022. 최초 실행 플랫폼 [Pending]

모바일 이용은 확정이며 모바일 웹·PWA·네이티브 앱 중 기술 선택은 미정이다. 초기에는 모바일 웹을 우선 기술 후보로 검토한다.

### D-023. 콘텐츠 발행·사실 확인 정책 [Pending · Critical]

원문 근거, 충돌 보도, 불확실성 표시, 자동 검사와 수동 검토가 필요한 경우를 정의한다.

### D-033. 편집 정책 [Pending] (v1.1 추가)

정치 공방성 콘텐츠와 실질적으로 중요한 정책·사회 이슈의 경계, 사회적으로 중요한 사건을 놓치지 않기 위한 기준을 별도 편집 정책에서 구체화한다. 정책을 정하기 전에는 임의의 정치적 판단을 코드로 고정하지 않는다. (P-09, PRD FR-B-18)

### D-034. 프로필 삭제와 과거 평가 기록 보존 [Confirmed — 2.5절로 옮김, v1.4] (v1.1 추가)

실패 사례를 다시 실행하려면 당시의 프로필 내용이 필요하고(P-12), 사용자는 자신의 정보 삭제를 통제할 수 있어야 한다(P-10). 삭제 시 과거 기록에 남은 프로필 내용을 지울지, 가릴지, 기간을 두고 보존할지 정한다. 확정된 것은 삭제한 정보를 이후 추천과 집필에 쓰지 않는다는 점까지다. (PRD T-04)

PRD 8.2절의 기술 미결정 항목(T-01~T-11) 가운데 T-04는 D-034로 등록했고, T-07의 사진 이용 권리와 대체 시각 콘텐츠 제작 방식은 D-012와 D-016의 v1.1 추가 조건에 반영했다. 나머지 항목은 이 로그에 올리지 않았다. Technical Discovery에서 다루며, 결정이 나면 이 로그에 기록한다.

## 4. 대체된 과거 개발안

- 외부 8~12명 대상 선행 실험 → 최초 개인용 MVP와 반복 사용 평가로 대체. 외부 검증은 다음 단계.
- 인터랙티브 설명 후순위 → 최초 MVP 필수.
- 정적 캐릭터만으로 종료 가능 → 최소 실제 애니메이션·상호작용 필수.
- 기본 추천으로 만족 → 정확성을 평가·개선하는 다단계 구조가 핵심. 단순 구현은 비교 기준선으로 허용.
- 대화형 첫 가입 구현 → 최초 MVP에서는 직접 입력. 장기 비전은 유지.
- (v1.1 추가) 시각화가 불필요한 콘텐츠에는 강제하지 않음 (P-15의 문장) → 모든 소식에 시각 요소 필수 (D-039).

v1.1에서 Superseded로 바뀐 Confirmed 결정은 없다. D-007과 D-008은 내용이 뒤집힌 것이 아니라 D-024~D-027, D-031, D-039로 보완되었다.
