# Product Brief

**개인화 뉴스 서비스 | v1.0 · 승인된 제품 정의 | 2026-11-13**

## 1. One-liner

뉴스를 읽을 힘도 없는 현생에 지친 20대에게, 나를 아는 작은 새가 나에게 딱 알맞은 소식을 골라 프리미엄으로 전달한다.

## 2. Product Vision

바쁜 일상 속 세상 소식에 대해 궁금한 사람들은 저마다 필요한 소식이 다르다. 너무 많은 뉴스 피드와 이슈, 자극적인 사건사고를 모두 흡수할 필요는 없다. 그 사람의 성장, 쉼, 생활, 미래, 커리어, 행복을 위해 의미 있는 소식을 찾고 싶지만 직접 뒤지고 이해할 힘은 부족할 수 있다.

우리는 사용자가 직접 탐색하지 않아도, 세상을 폭넓게 살펴 그 사람에게 의미 있는 소식을 발견하고 이해하는 즐거움을 제공한다.

사용자는 자신을 이해하는 소식 전달 캐릭터로부터 콘텐츠를 전달받고, 읽는 동안 흥미와 재미를 느끼며, 읽고 난 뒤 유익함과 성취감을 얻는다. 소식은 기존 뉴스 콘텐츠보다 훨씬 개인화되고 머리에 남는 알맹이가 많은 프리미엄 지식 콘텐츠처럼 느껴져야 한다.

## 3. Target Customer

### 최초 목표 사용자

29살, 뉴스 소비 피로가 높고 일상에 지친 우이음(여성). 업무와 일상에 지쳐 밤에 뉴스를 열었다가 어렵고 피곤한 콘텐츠를 피해 쇼츠로 이동하는 패턴을 갖는다.

- 세상 돌아가는 일을 알아야 한다는 욕구가 있다.
- 뉴스 소비가 어렵거나 피곤하다고 느낀다.
- 뉴스레터, 지면신문, 뉴스 피드를 꾸준히 이용하는 데 실패한 경험이 있다.
- 짧은 휴식시간에 유익한 콘텐츠를 보고 싶지만 탐색하기는 귀찮다.

### 최초 MVP 검증 범위

첫 번째 MVP는 창업자 본인 한 명을 대상으로 구현하고 검증한다. 다중 사용자 가입·운영 시스템보다 본인의 정보를 충분히 반영했을 때 핵심 가치가 실제로 구현되는지 확인한다. 이 단계의 합격은 개인적 사용 경험의 합격이며, 시장 수요나 타 사용자에게 일반화할 수 있는 검증은 아니다.

## 4. Problem Statement

목표 사용자는 뉴스에 관심이 없는 사람이 아니다. 알고 싶지만 필요한 정보를 찾고 이해하는 데 드는 에너지에 비해 즉각적으로 얻는 만족이 작다.

- 탐색 비용: 수많은 뉴스 중 나와 관련 있는 소식을 직접 찾아야 한다.
- 이해 비용: 낯선 용어와 맥락을 별도로 검색하고 해석해야 한다.
- 감정적 비용: 뉴스를 읽는 행위가 휴식보다 공부와 숙제처럼 느껴진다.

기획자 본인을 포함한 초기 VOC에는 탐색 피로, 이해의 어려움, 낮은 재미, 콘텐츠가 쌓이는 부담에 관한 사례가 있다. 이는 초기 문제 탐색 근거이며 대표성 있는 시장 조사 결과는 아니다.

## 5. Jobs To Be Done

하루 일과를 마치고 조금 쉬고 싶지만 세상과 단절되기는 싫을 때, 내게 의미 있는 소식을 누군가 대신 찾아 쉽게 설명해 줬으면 좋겠다. 그래서 시간을 쓰고도 무언가를 배웠다는 만족과 휴식을 느끼고 싶다.

### 기능적 Job

- 나와 관련 있는 뉴스를 쉽게 발견한다.
- 별도의 검색 없이 중요한 내용을 이해한다.
- 10분 이내의 적절한 시간에 소식 소비를 마친다.

### 정서적 Job

- 뒤처진다는 불안과 뉴스 소비의 부담을 줄인다.
- 나를 위해 준비된 콘텐츠라는 느낌을 받는다.
- 유익한 시간을 보냈다는 성취감과 휴식을 얻는다.

### 관계적 Job

- 새 캐릭터와 반복적으로 만나 친숙함을 형성한다.
- 서비스를 반가운 소식 전달자로 경험한다.
- 새와의 상호작용에서 펫과 함께하는 듯한 귀여움과 힐링감을 느낀다.

## 6. Value Proposition

나에게 필요한 세상 이야기를 골라, 이해하기 쉽게, 마음 편하게 건네주는 AI 새 친구.

### A. Personal Relevance

사용자의 실제 상황과 관심을 기반으로 뉴스 연결고리를 찾고, 선정한 이유를 이해 가능한 형태로 설명한다.

### B. Meaningful Understanding

필요한 배경지식과 용어를 쉽게 설명한다. 이해를 돕는 시각적·인터랙티브 설명은 내용상 필요한 경우 활용한다.

### C. Emotional Experience

새는 소식을 가져오는 전·중·후 과정과 설명에 참여해, 자신을 아끼는 전달자가 정성껏 설명하는 느낌을 제공한다. 정해진 콘텐츠만 최고 품질로 제공해 피드 피로를 줄이고 명확한 종결감을 만든다. 읽지 못한 날에도 부담을 느끼지 않게 한다.

## 7. Product Concept

### 7.1 온보딩 — 장기 제품 비전

사용자는 새 캐릭터와의 즐거운 대화를 통해 정보를 자연스럽게 나눈다. 새도 자신을 소개하고 사용자는 관심 분야, 선호하는 이야기, 하는 일, 생활 상황, 고민, 거주 지역, 원하는 소식 도착 시간 등을 선택적으로 공유한다. 예컨대 오목눈이 캐릭터가 자신의 가족 이야기를 먼저 들려주는 방식으로 관계를 형성할 수 있다.

### 7.1a 최초 MVP 온보딩

첫 개인용 MVP에서는 복잡한 대화형 온보딩을 구현하지 않는다. 모바일 화면에서 사용자가 직접 정보를 입력·열람·수정·삭제한다. 처음에는 소수 항목만 입력하되 나중에 매우 구체적인 정보로 확장할 수 있게 설계한다. 장기 제품의 대화형 온보딩 비전은 유지한다.

### 7.2 뉴스 탐색과 선별

AI가 뉴스 데이터를 수집하여 중복 보도를 사건 단위로 묶고, 사용자 정보와 사건 사이의 연결고리를 평가한다. 후보 사건의 관련성, 중요성, 새로움, 다양성, 신뢰성 및 추천 이유를 검토한다. 추천 기술은 최초 MVP의 핵심이므로 검증 가능하고 실패 원인을 추적할 수 있게 설계한다.

### 7.3 후보 뉴스 확정 및 집필

AI가 최종 검토한 사건을 사용자에 맞게 집필한다. 사건 선정과 집필은 별도의 평가 단계로 운영해, 표현 품질이 뛰어나더라도 관련성이 낮거나 사실이 틀린 콘텐츠가 통과하지 않도록 한다.

### 7.4 콘텐츠 경험

소식에는 핵심 사실, 사용자와의 관계, 배경지식, 개념 설명을 포함한다. 사진과 시각화를 적절히 활용해 프리미엄 지식 콘텐츠 수준으로 편집한다. 최초 MVP에는 AI가 뉴스 내용에 적합한 인터랙티브 설명을 구성하는 기능이 필수이며, 단순 텍스트 요약만으로 완료하지 않는다. 승인된 인터랙티브 컴포넌트와 구조화된 데이터 활용을 기술 방향으로 우선 검토한다.

### 7.5 마무리

정해진 소식이 끝나면 추가 뉴스 피드 없이 캐릭터와의 상호작용이나 대화로 자연스럽게 전환한다. 정보 소비 피로를 낮추고 휴식과 종결감을 제공한다.

### 7.6 지속적 개인화

사용자가 명시한 선호와 허용된 피드백을 통해 추천 품질을 개선한다. 장기 기억의 범위·보관기간·추론 데이터의 처리는 별도 기술·개인정보 설계에서 결정한다.

## 8. Differentiation

| 기존 뉴스 경험의 한계 | 본 서비스의 차별화 방향 |
| --- | --- |
| 인기·주제 중심 추천 | 사용자 삶과 연결되는 정교한 사건 선정 |
| 단순 요약 | 이해와 기억을 돕는 프리미엄 지식 콘텐츠 |
| 텍스트·이미지 중심 기사 | 내용에 맞는 AI 인터랙티브 설명 |
| 정보 전달 중심 | 새가 전하고 설명하는 감성적 경험 |
| 끝없는 피드 | 적은 수의 고품질 소식과 명확한 마무리 |

실제 시장의 차별성은 경쟁 서비스 조사 및 외부 사용자 검증을 통해 별도 확인한다.

## 9. MVP — Personal Core Experience MVP

### 9.1 목적과 합격 조건

최초 MVP는 창업자 본인 한 사람에게 Personal Relevance, Meaningful Understanding, Emotional Experience 세 가지 핵심 가치가 실제로 전달되는지를 검증하는 개인용 제품이다. 세 가치 중 하나라도 충족되지 않으면 MVP 전체를 통과로 보지 않는다.

### 9.2 CORE A — 개인 프로필 관리

- 모바일에서 사용자 정보를 직접 입력한다.
- 핵심 정보로 시작해 직업·관심사·생활 맥락·최근 고민·배경지식을 점진적으로 추가한다.
- 입력 정보를 열람·수정·삭제할 수 있다.
- 직접 제공한 사실과 AI가 추론한 정보를 구분한다.
- 구조화 필드와 서술형 필드를 함께 활용할 수 있는 확장형 데이터 모델을 검토한다.

### 9.3 CORE B — 뉴스 수집, 사건 정리, 개인화 추천

- 사용 권리가 확인된 뉴스 데이터를 이용한다.
- 같은 사건의 중복 보도를 사건 단위로 묶고 출처와 시간을 보존한다.
- 사용자와 사건의 연결고리를 도출하고 관련성·중요성·새로움·다양성·신뢰성을 평가한다.
- 억지 연결은 만들지 않으며 추천 이유를 근거에 대조한다.
- 선정·제외 이유를 기록하고 잘못된 추천의 원인을 추적한다.
- 실제 평가 사례를 이용해 품질을 반복 개선한다.

### 9.4 CORE C — 개인화 프리미엄 집필

- 확정된 사건의 사실관계를 원문 근거와 확인한다.
- 개인에게 맞는 설명 수준과 관점을 구성한다.
- 사건 의미·관련성·배경지식을 읽기 쉬운 방식으로 설명한다.
- 사실과 해석을 구분하고 시점·출처를 표시한다.
- 단순 요약이 아닌 흥미롭고 기억에 남는 콘텐츠를 목표로 한다.

### 9.5 CORE D — AI 인터랙티브 지식 콘텐츠

- AI는 설명 목적에 맞게 관계도·과정도·비교·조작형 예시 등을 선택한다.
- 사용자가 값이나 선택지를 바꾸며 이해할 수 있어야 한다.
- 시각화의 사실·숫자·논리가 출처와 일치하는지 검사한다.
- 모든 소식에 불필요한 인터랙션을 강제하지 않는다.
- 초기에는 승인된 컴포넌트에 검증된 구조화 데이터를 전달하는 방식을 우선 검증한다.
- 적합한 여러 뉴스 유형에서 실제 작동하는 인터랙티브 설명을 구현한다.

### 9.6 CORE E — 최소 감성적 새 경험

- 새가 등장·전달·반응·마무리를 담당하는 경험을 구현한다.
- 터치 시 간단한 반응이 발생하고 뉴스 읽기를 방해하지 않는다.
- Rive를 우선 기술 후보로 삼아 1~2일 규모의 제한된 캐릭터 프로토타입 작업을 진행한다.
- 해당 기간은 초기 상호작용 검증 목표이며 전체 애니메이션 완성 보장이 아니다.

### 9.7 CORE F — 모바일 읽기·마무리

- 모바일에서 제한된 수의 소식을 읽는다.
- 인터랙티브 설명을 조작하고 새와 최소한으로 상호작용한다.
- 무한 피드 없이 경험을 마무리한다.
- 최초 하루 소식 수량은 평가를 통해 결정한다.

### 9.8 최초 MVP에서 제외

다중 사용자 계정·가입, 외부 고객용 대화형 온보딩, 소셜·공유·스크랩, 결제, 캐릭터 수집·성장·복잡한 보상, 무한 뉴스 피드, 과도한 알림, 대규모 트래픽 대응, 정교한 실시간 캐릭터 게임. 단, 출처 확인·기본 보안·오류 처리·데이터 보호·품질 검증은 필수다.

### 9.9 완료 정의

서로 다른 날짜와 뉴스 유형에서 반복 평가하여 다음 모두를 확인한다.

- 관련성이 높은 소식이 실제로 추천되고 이유를 설명할 수 있다.
- 잘못된 추천과 주요 소식 누락을 찾아 수정할 수 있다.
- 콘텐츠가 개념 이해·흥미·기억에 기여한다.
- AI 인터랙티브 설명이 사실에 맞고 조작 가능하다.
- 새 경험이 유익한 읽기를 더 즐겁게 한다.
- 이용 후 피로보다 만족과 성취가 남는다.

정량 기준과 평가 기간은 검증 프로토콜에서 정한다. 본인 만족은 외부 시장 검증의 대체물이 아니다.

## 10. Success Metrics

### Personal Relevance

추천 관련성 점수, 추천 이유 정확도, 잘못된 연결 사례, 중요한 소식 누락, 중복·부적절한 후보 비율.

### Meaningful Understanding

핵심 개념 이해와 기억, 흥미, 추가 검색 필요성, 인터랙티브 설명 유용성, 출처와 사실 정확성.

### Emotional Experience

새 호감도, 전달받는 느낌, 터치 반응 만족, 이용 후 성취감·휴식감, 캐릭터 재방문 의향.

### 기술·품질

중대한 사실 오류, 출처 누락·불일치, UI 렌더링 및 조작 오류, 모바일 안정성, 추천·집필 처리시간, 운영 비용.

외부 사용자 유지율·매출·PMF는 최초 개인용 MVP의 합격 기준이 아니다.

## 11. Risks & Constraints

- 한 사람의 만족을 전체 시장으로 일반화할 수 없음; 창업자 평가 편향 가능성.
- 뉴스 저작권·API 이용권·AI 재가공 허용 범위 확인 필요.
- 후보군 누락·중복 사건 병합·잘못된 연결고리·환각 위험.
- 사실 오류 및 잘못된 시각화, 인터랙티브 UI 오류.
- 상세 사용자 정보·민감정보의 저장 및 AI 전달 위험.
- Rive 애셋 제작과 모바일 성능, AI 모델 지연시간과 비용.

## 12. Non-goals

대규모 상용 서비스, 외부 시장 PMF 입증, 유료 구독, 커뮤니티, 완전한 가상 펫 게임, 모든 뉴스 형식의 범용 자동 생성, 세계 모든 뉴스를 빠짐없이 실시간 수집하는 시스템.

## 13. Open Decisions

프로필 데이터 모델, 뉴스 공급원과 권리, 후보 수집 범위 및 갱신 주기, 사건 병합·랭킹 알고리즘, 집필 및 검증 파이프라인, 인터랙티브 UI 컴포넌트와 데이터 계약, Rive 에셋, 하루 소식 수, 개인용 MVP 평가 합격선, 기술 스택과 실행 환경. 이 항목들은 승인된 제품 방향과 구분하여 설계 단계에서 결정한다.

## 14. Development Path

1. 제품 원칙·가설·결정 기록을 개발 기준으로 고정한다.
2. 핵심 기능 PRD와 검증 기준을 상세화한다.
3. 뉴스 데이터 이용 권리·추천 파이프라인·인터랙티브 UI·Rive에 대해 Technical Spike를 수행한다.
4. 검증 결과를 Technical Design에 반영한다.
5. 기능별 Spec → Plan → Task → Implement → Test → Review 순서로 개발한다.
6. 창업자가 여러 날 실제로 사용해 세 핵심 가치를 평가하고 수정한다.
7. 개인용 MVP 합격 이후 외부 사용자를 대상으로 별도의 검증을 설계한다.
